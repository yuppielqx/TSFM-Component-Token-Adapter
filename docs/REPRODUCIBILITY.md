# Reproduction protocol

## Required artifacts

Stage I requires a local Chronos-Bolt checkpoint and a parquet `x` column of
historical contexts. Stage II requires the same backbone, the learned component
codebooks, and benchmark CSVs. Evaluation additionally requires a matching
`adapter_checkpoint.pt`. None of the datasets, component codebooks, or adapters
is tracked in Git. No verified public release URL for the latter two is
currently provided.

Keep the backbone revision and file hashes, codebook hashes, adapter metadata,
full command, random seed, package versions, and dataset hashes with each run.
An adapter trained with another codebook is not interchangeable just because
its embedding shapes agree. The download helper accepts `--revision COMMIT`
for a pinned Hugging Face snapshot.

## Data splits and scaling

`--data ett_h` uses ETT-hour boundaries at 12/16/20 multiples of 30 days;
`--data ett_m` uses the corresponding four-times-longer minute counts.
`--data custom` uses 70% training, 10% validation, and 20% testing.
The validation and test slices include the preceding input context. Scaling
statistics are fitted only on the training slice. Each variable becomes an
independent forecast example.

Do not evaluate an ETT result produced with `custom` as if it used the ETT
split. The removed historical all-dataset launcher used `custom` even for ETT.
The new `script/run_chronos_bolt.sh` explicitly selects the ETT loaders instead
and writes into `checkpoints/chronos_bolt/`, separate from older output paths.
Historical results are not reclassified or regenerated by this cleanup.

The model's decomposition uses only the available input window: a centered
25-point moving average with replicated boundaries, followed by phase means
of the detrended history. It is not STL. `period` is specified explicitly in
the launcher; it is independent of the dataset object's legacy metadata.

## Forecasting and metrics

The native Chronos-Bolt output covers 64 steps and nine quantiles. Evaluation
uses the median quantile. For a horizon greater than 64, the evaluator appends
its own median prediction, crops to the original input length, and calls the
model again. Decomposition, quantization, and token construction therefore run
again on each new context. No ground-truth future values enter that context.

MSE and MAE are calculated in the benchmark training-standardized units.
For a list of horizons, the evaluator uses one window population whose target
length is `--pred_len`, then takes prefixes for shorter horizons. Thus a joint
96/192/336/720 run uses only origins eligible for 720 steps. To evaluate every
eligible 96-step origin instead, run separately with `--pred_len 96 --horizons
"96"`. These two populations need not produce identical 96-step metrics.

## Direct commands

After preparing the backbone and codebooks:

```bash
python train_component_token_adapter.py \
  --data ett_h --root_path datasets/ETT-small --data_path ETTh2.csv \
  --features M --seq_len 512 --pred_len 64 --components "trend seasonal" \
  --pretrained_model_path checkpoints/base \
  --component_codebook_dir checkpoints/component_rqvae \
  --period 24 --n_rq_stages 2 --n_proto 256 --seed 2021 \
  --checkpoint_dir checkpoints/chronos_bolt/ETTh2 \
  --results_dir results/chronos_bolt/ETTh2/direct64

python eval_component_token_adapter_rollout.py \
  --data ett_h --root_path datasets/ETT-small --data_path ETTh2.csv \
  --features M --seq_len 512 --pred_len 96 --horizons "96" \
  --pretrained_model_path checkpoints/base \
  --component_codebook_dir checkpoints/component_rqvae \
  --adapter_checkpoint checkpoints/chronos_bolt/ETTh2/adapter_checkpoint.pt \
  --components "trend seasonal" --period 24 \
  --results_dir results/chronos_bolt/ETTh2/rollout96
```

Use `--max_train_batches`, `--max_val_batches`, and `--max_test_batches` for
local smoke runs only. Metrics from limited batches are not full-test results.

## Repository cleanup validation

The cleanup preserves the active backbone, residual-quantizer, Stage I, and
adapter computations. It removes obsolete external-context retrieval classes,
the earlier non-component discrete-code model, inactive datasets/utilities,
other backbones, private operational notes, and machine-specific launchers.
The removed versions remain recoverable in Git history.

Offline checks run with `python -m unittest discover -s tests -v`. They use
small synthetic fixtures and do not download model weights. Passing them is a
software check, not evidence that the complete paper experiments have been
reproduced or that GPU and CPU results are bitwise identical.
